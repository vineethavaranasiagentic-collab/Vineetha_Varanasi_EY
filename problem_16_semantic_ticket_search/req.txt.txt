Practical Problem: Semantic Search Over Client Support Tickets

Your company has a folder of about 200 old support tickets saved as plain text files, each containing a customer's issue description and how it was eventually resolved. Right now, when a new support ticket comes in, an agent has to remember or manually search through old tickets to see if a similar issue has been solved before, and keyword search misses most of the good matches because customers never phrase things the same way twice. Your job is to build a small ChromaDB-backed search tool that lets an agent type in a new customer's issue and instantly find the three or four most similar past tickets, ranked by actual meaning rather than shared keywords.

You will need to load the ticket files, chunk them sensibly since some tickets are long threads with multiple back-and-forth messages, generate embeddings for each chunk, and store them in a ChromaDB collection along with metadata like the ticket ID and resolution status. The search function should take a new issue description as input, embed it the same way, and return the closest matching chunks with their similarity scores, not just the raw text, so the agent can judge how confident to be in the match. Test it with a paraphrased query that shares no keywords with the original ticket, for example searching "app keeps logging me out" against a ticket that was originally described as "session expires randomly every few minutes," and confirm it still surfaces the right match near the top. You decide the chunking approach, the embedding model, and how many results to return. If your search correctly ranks the paraphrased query's true match in the top 3 results, you're done.
